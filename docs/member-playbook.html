Why the sprint is possible

Compressing five weeks into two only works because of three things, and the plan leans on all of them. First, the two components everything depends on — Packet and the emulator — already exist as drafts with 33 passing tests, so their rewrites are days, not weeks. Second, several tasks do not depend on anything else and have been moved to the front: Sinjan's timer heap and RTT estimator, and Sohini's receiver buffer, are pure data structures that can be built and tested before Packet lands. Third, experiments start on Stop-and-Wait and Go-Back-N data while Selective Repeat is still being finished.

The sprint is also exactly when copy-pasting gets tempting. Straight after exams, with a tight deadline, pasting a chatbot's Go-Back-N will feel reasonable. It is not: the viva is individual, sir will ask you to change your code live, and a chatbot gives every group the same answer to a textbook problem — which the brief treats as collusion. Use AI to understand. Type the code yourself.

Part 0 · Setup — everyone, by Tuesday 15 September

The repository folder is not shared. Sohan's copy lives on Sohan's laptop. Git is distributed: each of you makes your own complete copy on your own laptop by cloning it from GitHub, then works, commits and pushes from there. GitHub is only the meeting point. Every command below runs on your machine.

1. Install the tools on your laptop

Install Git and JDK 21 (Adoptium Temurin). On Windows, also set up WSL2, because the experiments must run on Linux:

wsl --install -d Ubuntu
wsl -d Ubuntu
sudo apt update && sudo apt install -y openjdk-21-jdk make python3-pip
java -version          # must print 21.x

2. Clone the repository onto your laptop

On Windows open Git Bash; on Mac open Terminal. Go to wherever you keep projects, then:

git clone https://github.com/sohan1611/rdt-udp.git
cd rdt-udp

You now have your own rdt-udp folder. Everything from here happens inside it.

3. Set your git identity — inside that folder

git config user.name  "Your Full Name"
git config user.email "your-github-email@example.com"
Use an email that is on your GitHub account, or you will not count as a contributor. Check it at github.com/settings/emails. If you would rather not use a personal address, that page also shows a private one ending in @users.noreply.github.com, which links correctly. A commit with an unrecognised email shows a grey avatar and does not appear on your profile or in the contributor list. Sir treats commit history as evidence in individual moderation, so get this right once.

4. Check the build

./build.sh             # every suite must report 0 failed

5. Make your first commit — by Tuesday night

Open AI-USE.md, put your name against your role heading (replace _[name]_), and push it on a branch:

git checkout -b setup/your-name

git commit -m "Add my name to AI-USE.md"
git push -u origin setup/your-name
git log -1 --format='%an <%ae>'     # confirm the name and email are yours

Then open a pull request on GitHub. The first push asks you to sign in; on Windows a browser window opens, which is normal. Once this merges, you appear in the contributor list.

Part 1 · Rules for the sprint

Daily check-in — every night by 10 pm, in the group chat

Three lines, no more: done today, doing tomorrow, blocked on. In a two-week sprint a silent day costs half a day for whoever is waiting on you. If you are blocked, say so the same evening, not at the next gate.

Friday 18 September, 8 pm — conventions call

Thirty minutes, all four of us. We agree the decisions that let four people's code plug together on Monday 21: the protocol interface, what sequence and ACK numbers mean, the command-line flags, the RunStats fields and result line, and the trace format. Section 6 of every handbook lists the proposals. Shaili commits the outcome as docs/CONVENTIONS.md on Saturday morning.

Branches and pull requests

Never commit straight to main. One branch per task: m1/packet-rewrite, m2/timer-wheel, m3/receiver-buffer, m4/emulator-rewrite.

git checkout main && git pull              # always start from the latest main
git checkout -b m2/timer-wheel
# ... work, commit as you go ...
git push -u origin m2/timer-wheel             # then open the PR on GitHub

The explanation check still applies, even in a hurry. Before approving, the reviewer asks two or three why questions. Why this data structure? What happens if this ACK is lost? Why this bound? Commits

  • At least one commit every working day during the sprint, under your own name and email.
  • Never commit on someone else's behalf — the brief counts that as non-contribution by the absent member.
  • No Co-Authored-By lines, no bot pull requests, Dependabot stays off. The contributor list must show exactly our four names.

AI and libraries

Permitted: explaining concepts, debugging, reviewing your code, generating tests, boilerplate, plotting scripts, improving writing. Not permitted: generating the core protocol implementation and submitting it as your own. Log material help in AI-USE.md the same day. Banned: Netty, Aeron, KryoNet, JGroups, any QUIC library, and TCP anywhere on the data path.

Sinjan Mishra · M2 · Timers and Go-Back-N

You own everything to do with time: when to stop waiting, how long to wait, and what to resend. Your sprint is ordered deliberately — the timer heap and RTT estimator come first because neither depends on Packet, so you are never blocked on anyone in Sprint A.

Sprint A · 14–20 September

Mon 14 – Tue 15Setup and reading
  1. Complete Part 0. First commit pushed by Tuesday night.
  2. Read RFC 6298 — short, and exactly the Jacobson/Karels algorithm you will build.
  3. Read the Go-Back-N section of Kurose & Ross, chapter 3.
Done when: first commit merged, and you can say what SRTT and RTTVAR are.
Wed 16 – Fri 18TimerWheel
  1. Wednesday: a half-page design note in docs/ — what a timer heap is, why a single thread rather than a timer per packet, how the socket receive timeout comes from the earliest deadline. Commit it; it becomes part of your report section.
  2. Write TimerWheel.java: a PriorityQueue of deadlines from System.nanoTime(), with schedule, cancel, and earliest-deadline operations.
  3. Single-threaded. The socket loop asks the heap how long until the next timer and blocks in receive for exactly that long. A timeout and an arriving ACK are both just events on one loop, so there is no race between them.
  4. Do not use ScheduledExecutorService or java.util.Timer. They reintroduce exactly the concurrency the brief warns about.
  5. Tests: ordering under many insertions, cancelling an already-fired timer, identical deadlines.
  6. Wednesday evening: review Shaili's Packet PR and ask three why questions.
Done when: merged by Friday night, and the heap reports the correct earliest deadline after a randomised sequence of schedules and cancels. Sohini is waiting on this for Selective Repeat.
Be able to explain: how you avoid a race between a timeout firing and an ACK arriving — there is no race, and you should be able to say exactly why.
Sat 19 – Sun 20RttEstimator
  1. Implement Jacobson/Karels: SRTT = (1−α)·SRTT + α·R with α = 1/8; RTTVAR = (1−β)·RTTVAR + β·|SRTT−R| with β = 1/4; RTO = SRTT + 4·RTTVAR, clamped to a sensible minimum.
  2. Add Karn's algorithm: never sample RTT from a retransmitted packet — when an ACK arrives for a packet sent twice you cannot tell which copy it answers. On timeout, double the RTO instead, and resume sampling only after a clean, un-retransmitted exchange.
  3. Test against values you work out by hand on paper. It is the fastest way to catch an α/β mix-up.
Done when: merged by Sunday night, matching your hand-worked numbers.
Be able to explain: what Karn's algorithm protects against, with a concrete example · why RTO adds 4×RTTVAR instead of using SRTT alone.

  3. Plug in your RttEstimator for the timeout value.
  4. Run it through the integrity checks across 5 channel profiles and 10 seeds.
Done when: merged by Wednesday night, passing 5 profiles × 10 seeds — part of Gate 4.
Be able to explain: why Go-Back-N retransmits the whole window · why it needs W ≤ 2k−1 sequence numbers · why it falls behind Selective Repeat as loss rises.
