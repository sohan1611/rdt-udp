11 · How we work together

Nightly check-in — by 10 pm, in the group chat

Three lines, every night of the sprint. For example:

Done:     receive buffer releases 1,3,4,2 in order; 5 tests passing
Tomorrow: duplicate handling, then open the PR
Blocked:  nothing

In a two-week sprint, a silent day costs whoever is waiting on you half a day. If you are blocked, say so that evening — never save it for the next gate.

Branches

Never commit directly to main. Use one branch per task, named after your role — {{BRANCH}}/short-task-name. Always start from the latest main:

git checkout main
git pull
git checkout -b {{BRANCH}}/short-task-name

Bring main into your branch at least once a day, so you meet other people's changes while the conflicts are still small:

git fetch origin
git merge origin/main

Pull requests

Push your branch, open a pull request on GitHub, and use this description:

What:        one sentence
Why:         which playbook task this is
How tested:  the commands you ran and what they printed
Ask me:      two things you want the reviewer to question
WhenYour reviewer — and whose PRs you review
Sprint A · 14–20 September{{PAIR_A}}
Sprint B · 21–27 September{{PAIR_B}}

Review within 12 hours. An unreviewed PR blocks someone. If your partner is stuck, anyone else may review instead, and you review your partner's work on the same terms.

The explanation check. Before approving, the reviewer asks two or three why questions — why this data structure, what happens if this ACK is lost, why this bound and not another. If the author cannot answer, the PR does not merge. A five-minute voice call is enough. It rehearses the viva every day, and it catches copy-pasted code while there is still time to rewrite it.

Commits

  • At least one commit every working day of the sprint, under your own name and email.
  • Small commits whose messages say what changed — "Release buffered packets once the gap at rcv_base fills", not "update".
  • Never commit on someone else's behalf. The brief counts that as non-contribution by the absent member.
  • No Co-Authored-By lines, no bot pull requests, and Dependabot stays off. The contributor list must show exactly our four names.

Other people's files

If you need a change in a file someone else owns, message them first. If it is urgent and they are unreachable, make the smallest change you can, say so in your PR, and tag them. A merge conflict in a file is resolved by that file's owner.
